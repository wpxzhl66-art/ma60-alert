# 结果分享到微信群的可行方案设计

版本 v1.0.0 · 设计日期 2026-10-18 · 前置：docs/微信直推方案设计_v1.0.0.md
数据核实：企业微信官方帮助中心、GitHub 仓库状态（gh 实查 2026-10-18）

---

## 一、先回答核心问题

**「我创建的个人微信群」能不能作为程序化发送目标？**

- 微信**没有**为个人微信群提供任何官方机器人/接口。这是平台设计，不是技术缺口。
- 因此全自动直发个人微信群只剩「非官方协议/Hook」一条路（见方案 C），能跑但违反微信使用条款，有封号风险——如实告知，不作为推荐。
- 合规前提下的可行路径分三档，按「自动化程度 × 朋友配合门槛」排列如下。

---

## 二、方案 A（推荐）：推给自己 + 转发件自动化，两步进群

**思路**：程序不做「进群」动作（微信也不允许），而是把「转发成本」压到最低——每次推送顺带产出**现成的转发件**，你在群里两个动作完成分享。

**转发件形态（三选一或组合）**：
1. **每日结果长图**：工具在收盘确认时自动生成当日结果 PNG（复用现有 `chart.py` 出图能力，加一张汇总长图），存到看板 `dashboard/shots/` 固定地址。你手机上打开 → 保存 → 转发到群。图片在微信群里天然可读，不需要朋友点任何链接。
2. **稳定分享链接**：看板已在线（ma60-alert-dashboard.app.workbuddy.host），给 `app.js` 加一个 `?date=YYYY-MM-DD` 参数直达某日结果页；PushPlus 内容页 URL 同样可直接转群里，朋友微信内置浏览器打开即看。
3. **分享文案**：推送正文里附一段 3~5 行的「群发摘要」（结论 + 链接），长按复制即发。

**接口与流程**：无新接口——复用现有 Server酱/PushPlus 推送链路，仅新增长图生成（matplotlib，已有依赖）与 URL 参数渲染（前端小改）。
**限制**：需要你手动点两下（保存/复制 → 粘贴进群）；长图有个人信息（持仓/账户页不进图）需注意裁剪范围。
**优点**：零封号风险、朋友零门槛、当天可实施。

## 三、方案 B：企业微信互通群（朋友在微信里看，程序可全自动/半自动）

企业微信的「外部客户群/互通群」里，**微信用户可以在个人微信中直接收发消息**——这是唯一能让程序化消息合规进入普通微信用户会话的通道。

**两条子路径**：

### B1. 客户群群发 API（朋友留在微信群，不装任何 App）
- **接口**：企业微信「客户联系—群发助手」，API `add_msg_template`（创建群发任务）。
- **流程**：企业微信管理后台开通客户联系 → 创建互通群并拉朋友进群（朋友微信扫码加入）→ 工具调 API 创建群发 → **成员（你）在企业微信里确认发送** → 消息以你的名义落到群里，朋友在微信中收到。
- **限制（官方规则，已核实）**：
  - 每个客户群**每天最多接收 1 条**成员群发（管理员可配置为每天 1 条 / 每周 7 条 / 每月=当月天数，上限 31 条）；
  - **API 创建后需人工确认**，不是全自动；
  - 需要企业微信主体（个人可注册企业，客户联系功能的开放度以认证状态为准）；
  - 单条 4000 字，支持文本/图片/网页/小程序附件。
- **适配度**：「每天 1 条收盘汇总」正好卡在每日 1 条的额度内；但「盘中 5 轮扫描」没法都进群（可作为收盘汇总单条进群，盘中仍推给你自己）。半自动（每天点一次确认）。

### B2. 企业微信内部群 + 群机器人 Webhook（真全自动）
- **接口**：`POST https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx`，支持 text/markdown/图片，markdown 上限 4096 字节，**20 条/分钟**。
- **流程**：企业微信建内部群 → 群里添加机器人拿 webhook key → 工具直推，全自动、无额度焦虑。
- **硬限制**：**每个群成员都必须装企业微信 App**（内部群微信进不去）；官方明确机器人**不能**加入外部互通群——所以这条路对朋友有装机门槛。
- **适配度**：技术上是完美方案，取决于朋友是否愿意装企业微信。

## 四、方案 C：非官方协议/Hook（存在但不推荐，如实告知）

GitHub 上确实有直发个人微信群的开源项目（gh 实查 2026-10-18）：

| 项目 | 许可 | Stars | 状态 |
|---|---|---|---|
| wechaty/wechaty | Apache-2.0 | 23.4k | 框架活跃（2025-12 有 push），但网页版协议 puppet-wechat 已停更（2022-07），网页版登录入口对绝大多数账号已关闭；可用 puppet 依赖付费 pad 协议 token 服务 |
| lich0821/WeChatFerry | MIT | 6.8k | **仓库已归档**（archived=true，2026-07 最后 push），Windows 微信 Hook 注入方案，随微信版本更新易失效 |

- **原理**：模拟设备登录（iPad/Pad 协议）或注入 PC 微信进程（Hook），以你的微信号身份调用收发接口，可向任意群发消息。
- **流程**：本机常驻一个微信实例/协议客户端 → 工具调其本地 API 发群消息。
- **风险（为什么不做）**：违反微信个人号使用条款，**有封号风险**；Hook 方案随微信版本升级随时失效；WeChatFerry 已停止维护；以你的主号跑风险尤其不值。本次不实施、不代部署，仅作调研结论记录。

## 五、对比与推荐

| 维度 | A 转发件 | B1 互通群群发 | B2 内部群 Webhook | C 协议/Hook |
|---|---|---|---|---|
| 自动化 | 半自动（两步转发） | 半自动（每天确认） | **全自动** | 全自动 |
| 朋友门槛 | 零 | 零（微信进互通群） | 装企业微信 | 零 |
| 合规风险 | 无 | 无 | 无 | **封号风险** |
| 额度 | 无限制 | 每群每天 1 条（可配到 31 条/月） | 20 条/分钟 | 不稳 |
| 实施成本 | 半天 | 需注册企业微信+开通客户联系 | 低（但前提是 B2 群成立） | 高且不可靠 |

**推荐**：
- **先做 A**（今天就能上线）：收盘确认时自动产「当日结果长图 + 分享链接」，你转发到群。朋友零门槛、零风险，覆盖「让朋友看到结果」的本质需求。
- **朋友配合度高则升级 B2**（建企业微信内部群 + Webhook 全自动）；**朋友不愿装 App 但想要自动**则上 B1（互通群每日 1 条收盘汇总，程序创建、你每天点一次确认）。
- **C 不采用**。

## 六、方案 A 的实施细节（确认后执行）

1. `chart.py` 增加 `render_daily_summary()`：当日触发 TopN + 期货 + 形态汇总的竖版长图（720×1600 左右，微信友好），输出 `dashboard/shots/daily-YYYYMMDD.png`（gitignore 或随站点发布均可）。
2. `app.js` 支持 `?date=` 参数：打开即展示指定日结果（默认今天），供链接分享。
3. `run_notify` 尾部把长图 URL 与分享摘要附进推送正文（Server酱 desp / PushPlus content）。
4. 配置加 `share.enabled: true` 开关；不动推送护栏与额度逻辑。
5. 验证：真发一条 → 手机保存长图 → 转发测试群 → 朋友点链接核验。
