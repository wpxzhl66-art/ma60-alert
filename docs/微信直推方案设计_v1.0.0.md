# 微信直推方案设计（无需安装额外 App）

版本 v1.0.0 · 设计日期 2026-10-18 · 关联：docs/推送方案调研_v1.0.0.md（Bark 方案）、工具使用说明书 v1.3.0

---

## 一、现状与目标

**现状**：推送已走 Server酱，消息本身就在**微信里**（方糖服务号模板消息）。瓶颈只有一条——免费版 5 条/天，A股预警、期货、形态、新闻共用。

**目标**：结果直接送达微信、微信内直接浏览、不装任何额外 App，触达率尽量高、使用门槛尽量低，并解除 5 条/天的限制。

**需求量化**：交易日 5 轮扫描 + 收盘确认 + 数据更新 + 非交易日要闻汇总，极端情况每日 5~10 条；期望额度 ≥ 50 条/天才算无感。

---

## 二、微信内可用载体全景（含排除项）

| 载体 | 到达位置 | 触达率 | 定向单人 | 判定 |
|---|---|---|---|---|
| 认证服务号模板消息（Server酱/PushPlus/WxPusher 的底层） | 聊天列表「服务号/公众号」分组，带系统通知与红点 | **高** | ✅ | ✅ 采用 |
| 公众号测试号模板消息（自接官方 API） | 测试号会话，同公众号分组 | 高 | ✅ | ✅ 采用（自主路线） |
| 订阅号群发 | 订阅号折叠文件夹 | 中低 | ❌ 只能群发、1条/天 | ❌ 排除 |
| 小程序订阅消息 | 服务通知 | 高（单次） | ✅ 但**一次性授权**，每次推送都需用户先点一次授权；长期订阅仅政务民生等类目 | ❌ 排除 |
| 企业微信群机器人 Webhook | 企业微信 App 内部群 | — | 官方文档明确**机器人不能进外部互通群**，个人微信收不到；要在微信看就得装企业微信 App | ❌ 违背「不装 App」 |
| 个人微信任意模拟协议 | 聊天列表 | 高 | ✅ | ❌ 违反微信使用条款，封号风险，不碰 |

**关键结论**：个人微信合规开放的「服务器主动触达个人」通道**只有服务号模板消息一族**。各第三方服务（Server酱/PushPlus/WxPusher）本质都是把「服务号运维」包起来替你发；想不依赖第三方，就走测试号模板消息自己发。

## 三、候选方案的接收与查看路径

### 方案 A：PushPlus（第三方托管 · 门槛最低）★ 首选

- **开通路径**：官网 pushplus.plus 微信扫码登录 → 实名认证（约 1~2 元）→ 关注「PushPlus推送加」公众号 → 复制 token。全程约 10 分钟。
- **接收路径**：工具后台调 `http://www.pushplus.plus/send`（token + title + content）→ 消息以模板消息落在个人微信「PushPlus推送加」会话 → 点开即读，支持 html/markdown 正文，长内容自动生成内容页链接。
- **额度**：免费 **200 条/天**（对比 Server酱 5 条），对本工具 40 倍富余。
- **触达率**：服务号模板消息级，有系统通知；与 Server酱同档。
- **限制**：免费档有内容长度与频率软限制；依赖第三方存活与政策；实名认证多一步。

### 方案 B：微信公众号测试号模板消息（完全自主 · 无第三方依赖）

- **开通路径**：mp.weixin.qq.com 扫码开通**接口测试号**（无需认证、个人即可）→ 获得 appID/appSecret → 使用者个人微信扫码关注测试号 → 新建一个测试模板拿 template_id。开通 15 分钟，代码一次性写好。
- **接收路径**：工具后台自己调微信官方 API（`gettoken` + `message/template/send`）→ 模板消息落在测试号会话 → 点开即读；模板可带跳转 URL（点击直达看板）。
- **额度**：无条数级限制（受微信接口通用频率约束，测试号额度远超本工具用量）。
- **触达率**：与方案 A 同为模板消息路径，同档。
- **限制**：① 测试号官方定位是开发调试，**无长期稳定承诺**，理论上存在政策变动风险；② 模板内容为固定字段拼接，排版不如第三方灵活；③ 需要维护 access_token 刷新（7200s 缓存）。
- **许可/成本**：微信官方能力，零费用，零第三方。

### 方案 C：WxPusher（第三方托管 · 备选）

免费额度较宽松、走认证服务号触达，接入方式与 A 同级。作为 A 的替补：若 PushPlus 政策收紧可平移。精确额度未在本次核实，接入前查官网确认。

### 方案 D：Server酱付费（Turbo/³ 会员）

零改动，付钱把 5 条/天提到 200 条/天档。触达与现状完全一致。适合「不想动代码」的情形，作为兜底选项列出，不作为推荐。

## 四、推荐与选型依据

**首选：方案 A（PushPlus）**，理由按权重排序：
1. **门槛最低**：与现有 Server酱接入几乎同构（token + title + content），`pusher.py` 改造量最小，10 分钟开通。
2. **触达率高**：认证服务号模板消息，与现有 Server酱同一触达档位。
3. **额度解困**：200 条/天，覆盖最坏情况 20 倍。
4. **免费**：仅实名认证的小额费用。

**并行准备：方案 B（测试号）** 作为「去第三方化」备份。A 依赖第三方服务政策（免费档额度、服务存活），B 是官方 API 直连的终极自主路线；建议 A 先跑通，B 按需实施（代码兼容同一抽象层，切换只是换配置）。

**触达率排序说明**：A/B/C 三者底层都是服务号/公众号模板消息，触达同档，差异在开通门槛与额度；真正拉开触达差距的是「内容是否要再点一下才能看完」——见下一节。

## 五、内容呈现设计（决定实际触达效果）

模板消息单条容量有限（标题 32 字内、正文关键词字段各数百字），而现有推送正文可达 7000 字（Top30 名单 + 新闻栏目）。分层呈现：

1. **推送卡（微信内直接可读）**：
   - 标题 = 一句话结论，如「【收盘确认】触发 52 只，剔除 ST 后 50 只」；
   - 正文 = 前 5~8 条核心行（代码+名称+涨幅+偏离，纯文本表格化），控制在模板字段容量内；
   - 财经新闻栏目只给「N 条 · 前三条标题」，不塞全文。
2. **全文落点**：消息尾部固定附看板链接（现成 `ma60-alert-dashboard.app.workbuddy.host`），点击在微信内置浏览器直接浏览完整名单、K 线、新闻——**微信内打开网页不需要装任何东西**，这一步保住了「完整浏览」的体验。
3. **长文兜底**：PushPlus 的 html 正文本身支持长内容页（点卡片进内容页），测试号则靠模板 URL 跳看板。

## 六、与现有工具的集成设计

```
run_notify / run_manual_push
        │
        ▼
pusher.py（改造为通道抽象层）
  ├─ channel = serverchan   # 现状，5条/天护栏保留
  ├─ channel = pushplus     # 新增，200条/天，免费
  └─ channel = wx_test      # 备用，官方测试号模板消息
        │
        ▼
额度记账 push_state.json 按 channel 分键（互不挤占）
失败降级：主通道失败 → 自动落到备通道并记录（可选）
```

- **配置**（alert_config.yaml，local 不入库）：`push.channel`、`pushplus.token`、`wxtpl.appid/secret/template_id`。
- **护栏沿用**：`push.enabled` 总开关、dry-run、每日去重（alert_state.json）全部不动；`daily_limit` 仅对 serverchan 通道生效。
- **手动推送入口**（`--push`）自动跟随所选通道，无需另改。
- **改造量估计**：pusher.py +80~120 行，config +6 行，文档半节；半天内完成并真机验证。

## 七、风险与限制（如实列出）

| 风险 | 影响 | 缓解 |
|---|---|---|
| PushPlus 免费档政策变动（额度缩减/收费） | 触达降级 | 通道抽象层已就位，切换 WxPusher/测试号只改配置 |
| 测试号为官方开发用途，无稳定承诺 | 极端情况通道失效 | 仅作为备份路线，不作唯一依赖 |
| 服务号消息在聊天列表中被折叠进公众号分组 | 需多一次点击才能看到 | 系统通知与红点仍在，触达率受损有限；可在微信里把该服务号置顶（用户侧一次性操作） |
| 模板消息内容审核（微信平台对营销类内容管控） | 金融类措辞需中性 | 现有文案已是事实陈述（非荐股），保持口径即可 |
| 长内容被模板字段截断 | 尾部名单看不全 | 第五节分层呈现 + 看板链接兜底 |

## 八、实施清单（确认方案后执行）

1. 用户侧：注册 PushPlus 并实名、关注公众号、复制 token（约 10 分钟，需用户本人完成实名）。
2. 工具侧：pusher.py 通道抽象 + pushplus 通道 + 配置项；push_state 按通道记账。
3. 验证：dry-run → 真发一条测试 → 完整推送预览（含长内容分层）→ 看板链接微信内打开核验。
4. 文档：说明书 v1.3.1 增「推送通道」节；CHANGELOG v1.25.0。
5. 可选二期：测试号模板消息备份通道。
