# 工具注册信息完整性自检报告

版本 v1.0.0 · 2026-10-17 · 审计对象：本会话环境注册的全部工具

---

## 一、总体结论

**不通过。**

发现 1 项阻断、5 项警告、8 项提示。阻断项只有一个，但性质严重：系统声明了一个工具，运行时却调不动，声明与现实不符。

| 严重度 | 数量 | 说明 |
|---|---|---|
| 阻断 | 1 | 工具声明与实际可用性不一致 |
| 警告 | 5 | 缺失关键说明或命名易混，影响正确使用 |
| 提示 | 8 | 可用但有改进空间，不影响功能 |

命名冲突：未发现。全部 260+ 工具名称唯一，MCP 工具靠 `mcp__服务器__工具` 三段式前缀天然隔离。

---

## 二、审计范围与方法

- **A 层（深审）**：原生工具 24 个，逐个过七维核查（名称、描述、参数定义、必填校验、返回值、示例、错误处理）。
- **B 层（清单级）**：延迟加载的 MCP 工具约 240+ 个，按注册清单核查名称与描述，不逐个拉完整 schema（成本原因，已确认取舍）。
- 方法说明：A 层的审计对象就是本会话持有的函数定义原文。部分结论来自实测（文中标注「实测」）。

---

## 三、阻断项

### B-01 `automation_update` 声明存在，实际不可用

- **定位**：系统层声明了该工具及完整参数 schema（mode/rrule/scheduleType 等），实测通过延迟执行通道调用，返回 "Tool automation_update is not available in the current environment or configuration"。
- **影响**：调用方按声明发起定时任务操作必然失败。失败信息倒还算明确，不至于盲试，但声明本身成了假承诺。
- **建议**：二选一。环境确实没这个能力，就从声明里移除；能力存在但需先启用，就在错误信息里写清启用路径。

---

## 四、警告项（A 层深审发现）

### W-01 原生工具普遍没有「返回值说明」

- **定位**：Write、Edit、Bash、PowerShell、TaskCreate、TaskUpdate、SendMessage、DeferExecuteTool、present_files、Skill、Agent 共 11 个工具，schema 里完全不描述返回内容。Glob、Grep、TaskGet、TaskOutput 有描述但粒度粗。
- **影响**：调用方只能靠猜或试。比如 Edit 成功时返回什么、失败时错误长什么样，文档一个字没提。本次会话实测中，Edit 参数不匹配时报错信息倒是清楚，但这属于运行时行为，不是承诺。
- **建议**：给每个工具补一行返回值说明。不求详尽，「返回修改后的 diff」或「成功返回空，失败返回错误对象」这种粒度就够用。

### W-02 `Skill` 工具的注册名与调用名不一致（实测踩坑）

- **定位**：技能在磁盘上的目录名是 `unclecheng-reduce-ai-perception-v2__skillhub`，schema frontmatter 里的真名是 `humanizer`。本次用目录名调用，直接报 "Can not find skill"，最后只能直接读 SKILL.md 文件绕过去。
- **影响**：按注册清单里的名字调用会失败。这正是「名称唯一且可调用」维度的实际违规。
- **建议**：注册名与调用名统一。目录名做 ID、frontmatter name 做真名，两者至少要能互相解析；错误信息里附上「最接近的可用名」。

### W-03 B 层注册清单只列名字，不给描述

- **定位**：约 240 个 MCP 延迟工具在注册清单里只有 `mcp__服务器__工具` 形式的名称，没有一句话描述。只有 30 余个系统延迟工具带简介。
- **影响**：不加载 schema 就无法判断工具用途，选型全靠名字猜。`mcp__neodata__other` 这种名字完全无法判断。
- **建议**：注册清单给每个工具补一句 20 字内的用途描述，或至少给 `other` 这类无信息量名字的工具补上。

### W-04 近似名工具易混

- **定位**：`connect_cloud_service` 与 `workbuddy_cloud_service`，前者取凭证、后者是托管后端 API，名字高度相似。`mcp__neodata__margin`（个股两融）与 `mcp__neodata__margin_market`（市场两融）同理。
- **影响**：选错工具要等调用失败或结果明显不对才能发现。
- **建议**：描述开头第一句写清「本工具做什么、不做什么」，近似名工具互相提一句。

### W-05 系统提示与工具描述双源，且互相引用

- **定位**：大量使用规则（如 Bash 的沙箱说明、Agent 的子代理类型清单、新闻/办公类 skill 的路由规则）写在系统提示而非工具 schema 里。schema 单独看是不完整的。
- **影响**：只拿 schema 做集成或测试的调用方会漏掉关键约束，比如「探针会断言用户可见文案」这类规则根本不在任何 schema 里。
- **建议**：把影响调用正确性的硬约束（必填前置、平台限制、超时默认值）收进 schema 描述；系统提示只留路由和偏好类软规则。

## 五、提示项

| 编号 | 工具 | 问题 | 建议 |
|---|---|---|---|
| T-01 | ToolSearch | 参数名 `tool_names` 非直觉，本次实测误传 `names` 直接报错；相关性排序会把无关工具混进结果（查 automation_update 时返回了 GitHub 工具） | 描述里给参数名示例；结果按匹配度排序并标注匹配原因 |
| T-02 | show_widget | 要求先调 widget_guidelines，这个前置约束只写在描述里，schema 层无校验，跳过前置会得到运行时错误 | 错误信息中明确提示「先调 widget_guidelines」；或 schema 加依赖声明 |
| T-03 | AskUserQuestion | schema 里有 `answers` 属性，供权限组件回传用，普通调用方不需要也不该填，易误用 | 描述里注明「调用方勿填此字段」或从对外 schema 拆除 |
| T-04 | Bash / PowerShell | 双 shell 入口，语法、引号、沙箱规则分叉，跨平台脚本容易踩错 | 两边描述开头各用一句写清适用平台与禁用语法 |
| T-05 | Skill | `skill` 与 `command`（legacy）两个参数功能重复 | 描述里明确「新代码只用 skill」，或移除 legacy 参数 |
| T-06 | 多数 A 层工具 | 无独立调用示例章节（部分在描述正文里嵌了） | 高频工具（Edit、Bash、Agent）补一个最小示例 |
| T-07 | library_search / mcp__space-library__library_search | 系统工具与 MCP 工具同名前缀，路由文档里只写「library_search」，实际调用路径不同 | 路由文档写全限定名 |
| T-08 | Read | offset 超出文件末尾时的行为未说明（文件不存在有说明，越界没有） | 补一句「越界返回空内容」 |

## 六、合格工具及已核对项目

以下工具七维核查无阻断、无警告，仅有 T 级小瑕疵或不计问题。列出已核对项：

| 工具 | 已核对项 |
|---|---|
| Read | 名称唯一；描述详尽（含图片/PDF/notebook 支持）；参数 file_path 必填、limit/offset 可选且类型明确；必填校验有（缺路径报错）；错误处理明确（文件不存在返回错误而非中断）|
| Glob | 名称唯一；pattern 必填、path/limit/offset 可选且 limit 默认 100、offset 默认 0；返回值有说明（按修改时间排序 + 分页）；描述内嵌 pattern 示例 |
| Grep | 名称唯一；17 个参数全部有类型与说明，output_mode 是枚举；返回值按模式分别说明；内嵌正则转义示例；必填校验明确 |
| WebFetch | 名称唯一；url/prompt 双必填；缓存、重定向、二进制限制、MCP 优先级全部写清；错误处理明确（重定向需重新请求）|
| WebSearch | 名称唯一；query 必填且最短 2 字符；freshness 有格式约束；返回值说明明确（搜索结果块）；使用时机指导充分 |
| AskUserQuestion | 名称唯一；questions 结构化定义，选项 2-4 个、header 12 字符上限、禁自带「Other」选项均有约束；返回用户答案（仅 T-03 小瑕疵）|
| TaskGet / TaskList / TaskOutput | 名称唯一；参数与默认值齐全（TaskOutput 的 block 默认 true、timeout 默认 60000 均写明）；返回值有说明 |
| Agent | 名称唯一；prompt 必填，mode/model/name/resume/max_turns 等 9 个可选参数全部有约束说明（名称唯一性规则、模式枚举、模型取值）；返回值流向说明明确（结果只回给调用方）|
| widget_guidelines | 名称唯一；modules 参数支持数组、JSON 字符串、逗号分隔三种形态且已写明；返回设计规范内容 |
| DeferExecuteTool | 名称唯一；双必填参数明确；错误行为有说明（校验失败返回 InputValidationError）（仅缺返回值细节，归入 W-01 统计）|

## 七、B 层清单核查结果

- **命名唯一性**：通过。三段式命名（`mcp__服务器__工具`）无重复，跨服务器同名被前缀隔离（如 agent-mail 与 tdx 都有自己的消息类工具，不冲突）。
- **命名分组**：14 个 MCP 服务器 + 系统延迟工具，前缀与连接器状态表一致，无「清单里有、连接器里没有」的孤儿服务器。
- **描述缺失**：见 W-03，这是 B 层最大的问题。
- **实测异常**：`automation_update` 属系统层声明，见 B-01。

---

## 八、修改建议汇总（按优先级）

1. 移除或修复 `automation_update` 的声明（阻断，必须处理）。
2. 统一 Skill 注册名与调用名，报错时给出最近可用名（W-02）。
3. 给 11 个无返回值说明的原生工具各补一行返回描述（W-01，一次批量改完）。
4. B 层注册清单补一句话描述，重点处理 `other` 等空泛名（W-03、W-04）。
5. 把影响调用正确性的硬约束从系统提示收进对应 schema（W-05，可渐进做）。
6. T 级 8 项按顺手程度逐步处理，不阻塞。
